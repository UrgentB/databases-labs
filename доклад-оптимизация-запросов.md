# Доклад: Оптимизация запросов в PostgreSQL

## Отслеживание неэффективных запросов

### Где настраивать?

- **Файл конфигурации:** `postgresql.conf`

### Ключевой параметр

- **`log_min_duration_statement`**

### Что делает?

- Записывает в лог все SQL-запросы, время выполнения которых **превышает заданное значение** (в миллисекундах).

### Примеры настройки

```text
-- Логировать все запросы дольше 1 секунды (1000 мс)
log_min_duration_statement = 1000

-- Логировать абсолютно все запросы (для отладки, опасно на проде!)
log_min_duration_statement = 0

-- Отключить логирование по длительности
log_min_duration_statement = -1
```

## EXPLAIN

Explain - это команда, которая показывается как Postgres будет выоплнят написанный после explain запрос

### Пример вывода EXPLAIN

**Запрос:**

```bash
EXPLAIN SELECT * FROM Users;
QUERY PLAN
-----------------------------------------------------
Seq Scan on users  (cost=0.00..13.20 rows=320 width=222)
```

Параметры:

- cost - стоимость запроса в условных еденицах;
- rows - сколько строк запрос затронет;
- width - средняя ширина строка в байтах.

Типы стратегий:​

- Seq Scan (Sequential Scan) — Последовательное сканирование;
- Index Scan — Сканирование по индексу​;
- Index Only Scan — Сканирование только индекса;​
- Bitmap Scan — Битовое сканирование​.
​

### EXPLAIN (ANALIZE)

Главное отличие от обычного explain - запрос действительно выполняется

```bash
postgres=# EXPLAIN (ANALYZE) SELECT * FROM Users;
                                   QUERY PLAN                                    
---------------------------------------------------------------------------------
 Seq Scan on users  (cost=0.00..13.20 rows=320 width=222) 
                     (actual time=0.039..0.041 rows=4 loops=1)
   Buffers: shared hit=1
 Planning Time: 0.276 ms
 Execution Time: 0.058 ms
(4 rows)
```

Помимо предыдущих парамтров добавляется действительных значений. Также указывается как Postgres взаимодействовал с памятью.

Параметры буфера:​

- Hit - данные были в ОЗУ;​
- Read - данные пришлось читать с диска;​
- Dirtied - "грязные" данные в ОЗУ;
